1 · Training in Colab

The notebooks came to Drive with the Colab package ({{ drive }}/notebooks/). If the package is older than this version of the trainer: create a new package on Ready for Colab? and upload it to {{ drive }}/packages - renders are kept.

  1. 2_render - renders the training images (one run with a mix of normal throws, dice kept at the wall and tilted dice).
  2. 3_detector - finds the dice. The first time from scratch, later optionally from the previous run (START_FROM).
  3. 4_classifier - recognises the symbol.
  4. Or 5_all_in_one - 2, 3 and 4 in one session (e.g. overnight), after notebook 1.

The detector and the classifier write their result to {{ drive }}/projects/{{ folder }}/export/ at the end.

Fetch the export to the computer

In Google Drive: My Drive → {{ drive }} → projects → {{ folder }}, right click on export → Download. Drive packs the folder as a ZIP into your downloads. Then in PowerShell (an existing export folder is renamed first, nothing is overwritten):

if (Test-Path "{{ r_export }}") { Rename-Item "{{ r_export }}" ("export_backup_" + (Get-Date -Format yyyyMMdd_HHmmss)) }
$zip = Get-ChildItem "$env:USERPROFILE\Downloads\export-*.zip" | Sort-Object LastWriteTime | Select-Object -Last 1
Expand-Archive -Path $zip.FullName -DestinationPath "{{ r_project }}"
dir "{{ r_export }}"

If Drive splits large folders into several ZIPs (…-001.zip, …-002.zip), unpack all of them one after the other with Expand-Archive into the same target.

3 · Firmware

What was in {{ r_firmware|path('models') }} before moves to {{ 'workspace'|path('firmware_models_backup/<date_time>')|safe }}. Repeat after every new conversion. To use the models in another firmware too, add --firmware <folder> (several times possible) - see docs/use_models_in_your_firmware.md.

Build and flash

In VS Code (ESP-IDF extension) open the folder {{ r_firmware }}, target esp32s3, Build, Flash, Monitor. Or in the ESP-IDF terminal:

cd "{{ r_firmware }}"
idf.py set-target esp32s3
idf.py build flash monitor

set-target only the first time. If several serial ports exist, add -p <port>. When flashing, the models go into their own flash areas (det, cls). The board's settings and Wi-Fi stay.

Then open http://pokerdice.local (or the board's IP address): the tab Play shows the hand, the live image with boxes and the symbols. Tab Monitoring: self-test of both models (“ok”) and the time per image.
